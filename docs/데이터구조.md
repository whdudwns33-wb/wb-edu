# 데이터 구조

타입 정의 원본: [shared/src/types.ts](../shared/src/types.ts). 모든 연결은 화면 표시명이 아니라 고유 식별자(UUID)로 합니다.

## 저장 방식

- `node:sqlite` 단일 파일. 집합(aggregate) 단위 문서 저장: `docs(kind, id, data JSON, version, updated_at, archived, is_sample)`.
- `version`: 낙관적 동시성 제어. 저장 요청은 현재 `version`을 함께 보내야 하며, 다르면 **409** (조용히 덮어쓰지 않음).
- `archived`: 삭제 대신 보관. 계획에서 항목을 제외해도 교재 원본은 삭제되지 않습니다.
- `is_sample`: 가상 샘플 표시. 설정 화면에서 샘플만 일괄 삭제할 수 있습니다. 데모 DB(`wb-edu.demo.sqlite`)와 운영 DB(`wb-edu.sqlite`)는 파일이 분리됩니다.
- `users`, `sessions`, `audit` 는 관계형 테이블.

## 식별자와 연결 규칙

- 실행 계획의 선택 필드 `learningApproach`는 `foundation` / `standard` / `fast` 중 처음 고른 시간 배분안이다. 과거 계획에는 없어도 되며 기존 JSON 문서 저장을 사용한다. `POST /api/plans/compare`는 세 가지 미리보기와 원천 버전(`sourceVersion`)을 반환하지만 저장하지 않는다. 선택 저장은 기존 `POST /api/plans`에 `learningApproach`와 `expectedSourceVersion`을 함께 보내며 변경된 원천을 조용히 적용하지 않는다.

- 배정 → 학습항목은 `textbookId + itemId`로, 교재 원본이 아니라 **계획 스냅샷** 안의 항목을 가리킵니다.
- `Curriculum.unassignedEntries`는 날짜 없는 과정 원천 미배정입니다. 이 목록이 남으면 실행계획 스냅샷을 새로 만들지 않습니다. `Plan.unassigned`는 차시에 배치된 분량을 달력에 편성한 뒤 남은 분량으로, 서로 다른 단계입니다. `PlanSnapshot`에 원천 미배정을 추가하거나 기존 저장 자료를 일괄 변경하지 않습니다.
- `LearningItem.prerequisiteItemIds`는 전교재에서 유일한 항목 id로 같은/다른 교재의 선수를 연결합니다. 새 교재 저장은 전교재 그래프를 검사하고 새 계획 스냅샷은 필요한 선수가 선택 교재 안에 있는지 검사합니다. 계획 확정 후 원본 교재의 선수 관계를 바꿔도 확정 스냅샷은 보존됩니다. 부분 차시 선택은 `selection.assumedDone`에 앞 차시의 학습 분량을 남깁니다.
- 이어서 진행 배정은 `continuedFrom`으로 원래 배정과 연결되며, 완료량은 항목 단위 합집합으로 계산되어 중복 집계되지 않습니다.
- 과정 복제는 새 id를 부여하고 검토 의견·버전·학생정보를 복제하지 않습니다. 계획 복제는 기록·이해 확인·이력·반/학생 식별·허용 강사를 제외합니다.

## 권한 (서버에서 검사)

| 작업 | 관리자 | 강사 |
|---|---|---|
| 교재·학습목표·표준과정·휴일·양식·운영 설정·사용자 관리 | O | 조회만 (과정 검토 의견은 가능) |
| 계획 만들기·수정·기록·확정·복제 | 모든 계획 | 자기가 만든 계획 + 허용 강사로 지정된 계획 |
| 샘플 데이터 일괄 삭제 | O | X |

인증: 세션 쿠키(`wb_session`, httpOnly, 14일). 비밀번호는 `scrypt`로 해시합니다.


## 2026-10-23 계정·외부 연동 확장

`UserRole`은 owner/admin/teacher다. 기존 사용자 ID와 문서 작성자 연결을 보존한다. `users.must_change_password`는 기본 0으로 추가하므로 기존 계정에 일괄 초기화를 강제하지 않는다. 신규 발급·관리자 재설정만 1이며 본인 변경 후 0이다. 외부 키는 `api_tokens`에 사용자 ID·이름·범위·해시·생성/만료 시각을 저장하고, 평문은 발급 응답에서만 제공한다. `api_requests`는 연결별 중복 키·입력 해시·상태·응답을 보관한다. 상태 0은 처리 결과 확인 전 상태이므로 재실행을 차단한다.

`PlanViews.halfYears`는 새 별도 계획 문서가 아니라 같은 실행계획의 학년도 기준 반년 집계다. `halfyear` 출력 수준과 양식 열 선택을 지원한다. 2026-10-23 운영에 계정 확장·API/MCP·반년 집계를 반영했으며 연결 방법은 [API-MCP-가이드.md](API-MCP-가이드.md)를 따른다.
