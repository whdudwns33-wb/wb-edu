# 자동 편성·재편성·진도 집계 규칙

구현: [shared/src/scheduler.ts](../shared/src/scheduler.ts), [shared/src/progress.ts](../shared/src/progress.ts), [shared/src/views.ts](../shared/src/views.ts), [shared/src/assembler.ts](../shared/src/assembler.ts)

## 1. 과정 조립판 (날짜 없음)

- 차시 예산 = 회당 수업시간 − 복습 − 여유.
- **순차형**: A교재 항목을 모두 배치한 뒤 B교재.
- **병행형**: 교재별 항목을 번갈아(라운드 로빈) 넣어 한 차시에 여러 교재가 들어가게 한다.
- **보충형**: 주교재 항목 순서대로 배치하고, `attachToItemId`로 연결된 보충 항목을 그 주교재 항목 바로 뒤에 붙인다. 연결이 없는 보충 항목은 미배정 목록에 남긴다.
- 보충 연결은 다른 교재의 항목을 제목으로 고른다. 새 연결·변경 연결은 보관되지 않은 다른 교재의 비제외 항목만 허용한다. 기존 연결은 대상이 나중에 보관·제외·삭제되어도 지우지 않으며, 화면에 상태를 알린다. 자동 구성에서 주교재 대상 항목을 사용할 수 없으면 보충 항목은 미배정으로 남는다.
- 같은 교재 안에서는 순서를 지킨다. 분할 가능 항목만 남은 시간에 맞춰 나누고, 분할 불가 항목은 다음 차시로 넘긴다. 어떤 차시에도 들어갈 수 없는 분할 불가 항목은 미배정으로 남긴다.
- 숙제 활동은 수업시간을 쓰지 않고 해당 항목이 배치된 차시에 붙는다.
- 나눌 수 있어도 한 단위(쪽·강) 분량이 회당 시간보다 큰 항목은 그 항목만 미배정으로 두고 뒤 항목은 계속 배치한다.
- 조각 묶기는 같은 차시 안의, 활동·트랙이 같고 범위가 바로 이어진 조각만 된다(12~15와 20~23은 묶지 않음). 나누기는 미배정 항목에도 된다.
- 과정 저장 검사: 배치 범위는 항목 범위 안의 정수 구간(시작 ≤ 끝), 비율은 0 초과 1 이하, 시간은 1~1000분 정수, 교재 사용 범위(포함·제외 항목) 안의 항목, 차시·배치 id 중복 없음, 한 과정의 두 교재가 같은 항목 id 를 쓰지 않음.
- 교재 저장 검사: 선수 학습은 같은 교재 또는 다른 교재의 항목을 교재명·판본·항목명으로 선택한다. 수정 후보를 포함한 전교재 그래프에서 항목 id 중복·없는 항목·자기 참조·순환(가→나→가)을 거절한다. 활성 항목의 선수로 사용 중인 항목은 삭제·제외하거나 교재를 보관할 수 없다. 관계를 먼저 명시적으로 정리해야 한다. 보관·제외된 출발 항목의 기존 관계는 보존하되 존재·순환은 검사하며, 사용할 수 없는 새 선수 연결은 거절한다. 이 교재를 쓰는 과정이 있는 항목을 지우거나 과정의 배치 범위 밖으로 항목 범위를 줄이면 저장하지 않고 과정 목록을 알린다. 범위를 넓혀 과정 배치가 새 범위를 다 덮지 못하면 저장하되 과정에서 고칠 곳을 알린다.
- 자동 구성 결과는 **초안**이며, 권장안을 가져왔다고 검증된 과정으로 표시하지 않는다. 검증된 과정의 구조를 바꾸면 과정 버전이 올라가고 상태가 초안으로 돌아간다.
- 자동 구성의 기본 트랙은 화면에 명시한 **현행**이며 복습·보충·선행을 선택할 수 있다. 보충형은 교재 조합 방식이고 복습·보충 트랙과 별개다. 보충 연결 항목의 활동은 선택 트랙과 관계없이 연습이다. 교재별 일괄 지정은 차시·미배정 배치의 `track`만 바꾸며 id·분량·활동·시간·순서·연결을 보존한다. 시간이나 선행 설정을 바꾸는 것만으로 기존 항목의 트랙을 바꾸지 않는다. 선행 설정이 있지만 선행 항목이 0건이면 경고한다.
- **과정 원천 미배정**(`Curriculum.unassignedEntries`)이 남으면 초안 저장만 허용하고 발행(검증됨 직접 저장 포함)·계획 미리보기·생성·초안 스냅샷 갱신을 동일 서버 검사로 거절한다. 필수/선택 모델이 없으므로 모든 원천 미배정을 막는 보수적 정책이다. 조립판에서 실제 차시에 배치하거나 포함·제외 범위를 명시적으로 정리하고 해당 배치를 빼야 한다. 범위를 자동 삭제하거나 가짜 차시·숙제로 옮기지 않는다. 정상 과정의 부분·중간 차시 선택은 유지한다.
- **달력 편성 미배정**(`Plan.unassigned`)은 원천 검사를 통과한 차시 분량을 실제 수업일에 편성한 뒤 남은 것이다. 기간·시간·선수 제약 등의 사유를 표시하고 계획 초안 저장은 허용하지만, 제외 처리되지 않은 분량이 남으면 확정하지 못한다. 원천 미배정을 달력 편성에서 누락시켜 해결하지 않는다.
- 새 계획 스냅샷은 배치 항목의 선수와 그 선수 관계를 따라 검사한다. 필요한 선수가 선택 교재 밖에 있거나 삭제·보관·제외되어 있거나 id 중복으로 모호하면 미리보기·생성·초안 갱신을 거절한다. 자동으로 교재를 추가하거나 외부 선수를 이미 배운 것으로 취급하지 않는다. 두 교재가 포함되면 관계를 스냅샷에 보존하고 선수 분량을 먼저 배정한다. 기존 확정 스냅샷과 실제 기록은 소급 변경하지 않는다.

## 2. 수업일 생성

- 한국 시간대의 실제 달력 날짜(`YYYY-MM-DD`)를 사용한다. 한 달 = 4주, 분기 = 12주 같은 고정 계산을 하지 않는다.
- 시작일~종료일(기간 우선) 또는 시작일~최대 탐색 일수(속도 우선) 중 **수업 요일**이면 수업일. 보강일은 요일과 무관하게 추가된다.
- 적용 공휴일·휴강일에 걸린 수업 요일은 `holiday`/`cancelled` 상태 수업으로 남겨 월간 보기에 표시하고 새 진도는 배정하지 않는다.
- 회당 새 진도 가능시간 = 회당 수업시간 − 복습 − 여유 − 그날 고정 일정 분.
- 기존 수업의 id·메모·점검 사항은 날짜 기준으로 보존되어 기록과의 연결이 끊기지 않는다.

- 종료일 뒤 보강일은 그 날짜만 수업일로 더하고, 사이의 정규 요일은 늘리지 않는다.
- 설정(요일·시작일·종료일 등)이 바뀌어 수업일이 아니게 되어도 **완료 기록·고정 배정이 있는 수업은 남긴다**. 이런 수업에는 새 진도를 더 넣지 않는다.
- 새 설정에서 그런 수업이 휴강·공휴일이 되거나 가능시간이 기록·고정 분량보다 작아져도 수업으로 남기고, 그대로 두었다고 경고한다.
- 휴강의 기준은 설정의 휴강일 목록이다(휴강 처리 연산도 여기에 기록). 목록에서 지우면 그 수업은 다시 수업이 된다.
- 계획 기간은 시작일부터 1100일(약 3년)까지다. 회당 수업·보강·고정 일정은 600분 이하, 복습·여유는 0분 이상이어야 한다.
- 휴강·공휴일 수업과는 맞바꿀 수 없고, 고정 배정이 있는 수업은 휴강 처리할 수 없다(먼저 고정을 해제하거나 옮긴다).

## 3. 채우기 (fill)

1. 과정 스냅샷의 차시를 순서대로 펼쳐 대기열을 만든다(숙제 제외). 트랙별(현행/복습·보충/선행) 대기열을 둔다.
2. 각 수업에서 트랙별 예산을 정한다.
   - 현행 최소 확보시간(`currentMinMinutes`)을 먼저 보장한다.
   - 선행 예산 = min(설정값, 가능시간 − 현행 최소). 선행 요일이 지정되면 현행 분량이 없어도 그 요일에만 새로 배정한다. 기록·고정 배정은 그대로 보호한다.
   - 복습·보충 예산 = min(설정값, 남은 시간).
   - 현행 → 복습·보충 → 선행 순으로 채우고, 남은 시간은 다음 트랙으로 넘긴다. 선행이 남긴 시간은 현행이 다시 쓴다.
   - 선행 목표일을 맞추려고 현행을 자동으로 줄이지 않는다.
3. 대기열을 앞에서부터 보며 항목을 넣는다.
   - 선수 학습 항목이 모두 배정(또는 완료)되어 있어야 한다. 아니면 그 교재의 뒤 항목도 이 수업에서는 건너뛴다.
   - 전체가 들어가면 넣는다. 안 들어가고 분할 가능하면 남은 시간만큼 앞부분을 나눠 넣고(범위형은 시간 비율로 쪽·문항을 나눔, 수량형은 5분 단위 비율), 나머지를 대기열 머리에 둔다.
   - 분할 불가이면서 앞으로 어떤 수업의 가능시간보다도 크면 **분할 불가** 사유로 즉시 미배정. 나눌 수 있어도 한 단위(쪽·문항) 분량이 그보다 크면 같은 사유다.
   - 범위형 항목은 범위가 2 이상일 때만 나눈다(과정 자동 구성도 같은 기준). 한 쪽짜리를 분량 비율로 나누지 않는다.
   - 같은 교재 항목은 순서를 지킨다. 다른 교재 항목은 앞으로 당겨 넣을 수 있다(병행).
4. 숙제는 같은 과정 차시의 수업 항목이 배정된 마지막 수업에 붙인다. 시간 부족을 해결하려고 수업 내용을 숙제로 바꾸지 않는다.
5. 남은 대기열은 사유를 구분해 미배정으로 남긴다.
   - **순서 제약**: 선수 항목이 계획 밖에 있거나 그 자체가 순서 제약으로 막힘(연쇄 판정).
   - **고정 일정 충돌**: 남은 수업의 가능시간이 고정 일정으로 모두 소진됨.
   - **목표일 초과**: 기간 우선이면서 종료일 없이 목표 완료일만 있을 때.
   - **총시간 부족**: 그 외(부족 분 합계를 경고로 표시). 붙일 수업이 없어 미배정이 된 숙제는 수업 시간을 쓰지 않으므로 부족 합계에 넣지 않는다.
   - 같은 교재는 순서를 지키므로, 순서 제약으로 막힌 항목 뒤의 같은 교재 항목도 **순서 제약**으로 분류한다(시간 부족 합계에 넣지 않음). 선수 관계가 서로 도는 항목도 순서 제약이다.
6. 속도 우선은 마지막 배정 수업까지만 남기고 완료 예정일을 계산한다. 목표 완료일을 넘으면 경고한다.
7. 같은 확정 입력은 같은 결과를 낸다(난수 없음).
8. 과정의 일부 차시만 계획하면(중간 지점부터), 선택 범위 앞 차시의 새 학습·연습 배치 분량은 이미 배운 것으로 보고 선수 조건 판단에 쓴다(`selection.assumedDone`). 이 명시적 선택은 스냅샷에 남아 갱신할 때 다시 적용된다. 선택 교재 밖의 선수를 충족했다고 보는 규칙은 아니다.

## 4. 안전한 일정 수정

공통: 모든 연산은 새 계획 상태를 반환하고 `history`에 `before`(배정 상태)를 남긴다. `dryRun`이면 저장하지 않고 **영향받는 수업·미배정 변화·종료일 변화**만 돌려준다. 완료 기록이 있는 배정과 고정 배정은 움직이지 않는다.

| 연산 | 동작 |
|---|---|
| 다음 수업 가능일로 미루기 | 그 수업의 움직일 수 있는 배정을 대기열 맨 앞에 두고 다음 수업부터 다시 채운다. 숙제는 수업 시간을 쓰지 않으므로 숙제 목록으로 보내 옮겨 간 차시 수업에 다시 붙인다. 기록이 있으면 거부 |
| 남은 범위 이어서 진행 | 부분 완료 기록의 남은 범위를 `continuedFrom`으로 연결해 다음 수업 맨 앞에 넣고 이후를 밀어낸다. 가운데를 먼저 마쳤으면(12~23 중 15~18) 남은 조각마다(12~14, 19~23) 넣는다. 남은 범위가 미배정이 되어도 연결을 유지해 두 번 이어서 진행할 수 없다 |
| 두 수업 맞바꾸기 | 기록·고정이 없을 때만. 선수 학습 순서를 어기면 차단, 가능시간 초과는 경고 |
| 특정 날짜에 고정 | 대상 수업에 추가하고 `locked`. 이전 날짜로 당겨도 기존 배정을 삭제·덮어쓰지 않고 초과를 경고 |
| 휴강 처리 | 휴강일로 등록 후 그 수업부터 재편성. 기록이 있으면 거부 |
| 보강일 추가 | 보강 수업을 만들고 그날부터 재편성 |
| 남은 일정 전체 재편성 | 지정일 이후의 움직일 수 있는 배정 + 미배정(제외 제외)을 원래 차시 순서로 다시 채운다 |
| 설정 변경 | 수업일을 다시 만들고(기존 id 보존) 전체를 재편성 |
| 되돌리기 | `before` 상태 복원. **가장 최근 변경부터 차례로만** 되돌린다(뒤의 변경이 말없이 사라지지 않도록). 해당 변경 **이후 입력된 실제 기록이 있으면 거부**하며 기록은 절대 지우지 않는다 |

재편성 연산은 유지한 배정(기록·고정)을 선수 항목 배정으로 보고 채우므로, 끝난 뒤 선수 순서가 새로 어긋났으면 '선수 순서 확인 필요'로 경고한다.

확정: 제외 처리되지 않은 미배정이 남아 있거나, 선행 과정의 기초 확인이 담당자 확인을 받지 않았으면 확정할 수 없다(초안 저장은 가능).

## 5. 진도 집계

### 학생 맞춤 3안 비교·선택

- 같은 과정·선택 학습 범위·요일·수업시간·휴일로 기초·보강형, 표준형, 빠른 진도·심화형을 비교한다. 기존 편성 엔진을 쓰고 비교 단계에는 계획을 저장하지 않는다.
- 검수용 기본 시간 배분은 `(회당 수업시간 − 여유 시간)`의 40% / 20% / 10%를 반올림해 복습으로 확보하며 새 진도는 최소 1분 남긴다. 교재 분량·난이도·트랙을 자동 변경하지 않는다. 기존 직접 설정 미리보기도 유지한다.
- 이는 학원의 확정 정책·학생 수준 진단이 아니다. 심화 내용은 과정에 등록되어 있어야 하며 앱이 문항을 생성하거나 범위를 생략하지 않는다. 수업이 짧으면 안별 결과가 같을 수 있다.
- 선택한 한 안만 초안으로 저장한다. 서버가 시간 배분을 다시 계산하고 비교 당시 과정·교재 버전과 다르면 409로 거절한다. 다시 비교한 뒤 저장해야 한다.
- 비교 요청은 당시 입력을 복사하고 처리 중 수업 조건·이전 버튼을 잠근다. 저장에는 선택된 서버 미리보기의 설정과 비교 당시 범위를 사용한다. 저장 중에는 다른 안으로 바꿀 수 없다.
- 속도 우선이며 미배정이 없을 때만 완료 예정일로 표시한다. 기간 우선 또는 미배정이 남으면 계산된 날짜는 마지막 배정일이며 미배정이 있으면 완료 예정일은 미정이다.
- 가상 과정에서 만든 선택 계획은 샘플 표시를 유지한다. `learningApproach`는 처음 선택한 안이며 이후 일정 수정은 가능하다. 다섯 보기·인쇄·엑셀의 편성 방식에 같은 선택안 정보를 표시한다.
- 기존 진도 기록·고정 배정 보호와 재편성 규칙은 그대로 적용하며 새 migration이나 기존 기록 일괄 수정은 없다.

### 진행 기록과 집계

- 새 진도 완료량은 활동이 **새 학습**인 배정의 기록만 센다. 복습·연습·평가·숙제로 같은 범위를 다시 진행해도 완료량은 늘지 않는다.
- 기록은 추가만 하며 **배정마다 가장 최근 기록만** 센다 (완료를 미진행으로 정정하면 완료에서 빠진다).
- 범위형(쪽·문항 등): 완료 범위들의 **합집합**으로 센다. 12~23쪽은 12쪽, 12~17쪽 완료 시 18~23쪽이 남는다.
- 수량형: 완료 비율 합(최대 1).
- 교재별·단위별로 따로 집계하고 서로 다른 단위를 섞은 비율은 만들지 않는다. 완료율 = 완료 ÷ (전체 − 제외). 기준 문구를 화면·출력에 표시한다. '제외'에는 제외 기록과, 미배정을 제외 처리한 범위가 모두 들어간다.
- 이해 확인이 학습목표를 골라 기록했으면 그 목표만 확인된 것으로 본다.
- 수량형 부분 완료의 %는 **이번 배정 분량 중** 몇 %인지다 (0.5 조각의 50% = 항목의 25%).
- 수량형 교재의 계획 범위 표시는 각 배정의 분할 비율 × 항목 전체 수량으로 계산하며 소수 둘째 자리까지 표시한다. 쪼갠 배정 하나를 전체 단원 하나로 세지 않는다. 연·분기·월·주·일 보기와 인쇄·엑셀에서 같은 집계를 쓴다.
- 같은 배정은 한 번만 이어서 진행할 수 있다.
- 배정한 숙제를 완료로 자동 처리하지 않는다. 제외는 사유가 필수다.

## 6. 5종 보기

- 모든 보기는 같은 `plan.lessons / assignments / records`와 같은 `summarizeLessons` 함수를 사용한다. 연간 = 분기 합 = 월 합 = 주 합 = 일 합.
- 주는 월요일 시작. 월을 걸치는 주는 각 월에 실제 수업일 기준으로 나뉘어 집계된다.
- 분기는 학년도 시작월(기본 3월) 기준이며, 달력 분기(`CQ`)와 학년도 분기(`AQ`)를 키로 구분한다.
- 인쇄·엑셀도 같은 `buildPlanViews` 결과를 쓰므로 화면과 범위·시간·버전이 일치한다.
- 교재별 범위는 교재·단위별로 따로 적고, 새 학습 범위와 복습·연습·평가·과제 범위를 나눠 적는다. 끊긴 범위는 처음~끝으로 합치지 않고 구간마다 적는다(12~23쪽, 36~47쪽).
- '배정 시간'은 차시에 배정된 모든 수업 활동(새 학습·복습·연습·평가)의 합이다. 일간 시간 배분은 매 수업의 '복습' 시간, '새 학습', '복습·연습·평가 활동'을 나눠 보여 준다.
- 출력 범위를 정하면 표지·총분량에 범위 안 수업 횟수·배정 시간을 계획 전체 분량과 따로 적는다. 날짜 형식이 틀린 범위는 화면·엑셀 모두 무시하고 전체를 쓴다.

## 7. 실제 소요시간 기반 개선 제안

구현: [shared/src/timing.ts](../shared/src/timing.ts)

- 진도 기록의 '완료'에 실제 분(선택, 1~600분)을 함께 적을 수 있다.
- 교재 편집 화면은 그 교재를 쓰는 모든 계획에서 **새 학습 배정의 완료 기록 중 실제 분이 있는 것**만 모은다. 복습·연습·평가·부분 완료·실제 분 없는 기록은 쓰지 않는다.
- 배정이 항목의 일부(분할·이어서 진행)라면 실제 분 ÷ 그 배정이 다룬 비율(범위형은 쪽·문항 수 비율, 수량형은 fraction)로 항목 전체 기준 분으로 환산한다.
- 환산값의 중앙값을 쓰고, 기록 3건 이상이며 현재 값과 20% 이상 차이 날 때만 5분 단위로 반올림한 값을 제안한다.
- 제안은 자동 적용하지 않는다. 담당자가 '반영'을 누르고 교재를 저장해야 하며, 이미 만든 계획의 스냅샷은 바뀌지 않는다.

## 8. 선수 학습 부족 시 보충 제안

구현: `supplementSuggestion` ([shared/src/objectives.ts](../shared/src/objectives.ts))

- 출발점은 선행 과정의 '필요한 기초 개념·확인 항목' 중 이 계획에 **이해 확인 기록이 없는** 목표다.
- 그 목표의 선수 목표는 `prerequisiteVerified`(검증 자료 또는 담당자 확인)인 관계만 따라가며, 이미 이해 확인된 목표는 빼고 연쇄로 모은다.
- 보관되지 않은 교재에서 그 목표에 연결된 학습항목(제외 항목 제외)을 찾아 보여 주고, 연결된 자료가 없는 목표는 따로 알린다.
- 관리자는 고른 항목으로 복습·보충 트랙의 **초안** 과정을 만들 수 있다. 자동으로 계획에 넣거나 선행을 줄이지 않는다.
- 담당자가 근거를 적고 '기초 확인'을 해야 선행 계획을 확정할 수 있다. 이 확인은 계획 스냅샷에만 기록되며 과정 원본은 바뀌지 않는다.

## 9. 학습목표 지도

- 상태: 계획에 배치됨 / 실제 진행함(완료·부분 기록) / 이해 확인 기록 있음 / 아직 배정되지 않음.
- 계획에 있다는 이유로 습득으로 표시하지 않는다. 같은 목표가 여러 번 나오면 반복 목적(복습·심화·평가)을 함께 보여 주고 자동 삭제하지 않는다.
- 선행 과정의 `requiredObjectiveIds` 중 이해 확인이 없는 목표는 "보충 과정 제안"으로 표시하고, 담당자 확인 전에는 확정을 막는다.


## 반년 보기 기준 (2026-10-23)

기존 학년도 시작월부터 연속 6개월을 전반기, 다음 6개월을 후반기로 집계한다. 예를 들어 3월 시작이면 3~8월, 9~다음 해 2월이다. 등록일부터 6개월이나 달력 반기로 해석하지 않는다. 기존 학년도 분기·월·주·일 집계와 같은 수업·배정·진도 기록을 사용하며 별도 계획이나 학습 범위를 자동 생성하지 않는다. 배정이 없는 구간은 내용·목표 미확정이다.
