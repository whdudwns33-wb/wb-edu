# 시범 운영 가이드 (실제 교재 1~2권, 반 1개, 2주)

목표: 실제 교재 1권 + 자체교재 1종으로 반 하나의 한 달 계획을 만들고, 2주 동안 매 수업 뒤 진도를 기록하면서
편성 규칙·화면·출력에서 고칠 점을 모은다. 학생 개인정보는 넣지 않아도 되며, 대상은 "초5 A반"처럼 반 이름만 적어도 된다.

## 0. 준비물 체크리스트

- [ ] 사용 범위가 확인된 **시중교재 1권** (목차·쪽수 확인 가능해야 함)
- [ ] **자체교재 1종** (활동지·평가지 등)과 주교재의 어느 단원에 붙는지
- [ ] 반 시간표: 요일, 회당 수업시간, 복습·여유로 쓸 시간, 시작일
- [ ] 2026년 학원 휴무일·방학·시험 대비 기간
- [ ] 강사 1~2명 계정으로 쓸 아이디·이름 (비밀번호는 각자 첫 로그인 후 변경)

## 1. 운영 모드 켜기 (데모 DB와 분리)

```bash
npm run build
```

```bash
npm run setup:prod
```

`.env.prod`가 없으면 만들어지고 초기 관리자 비밀번호가 무작위로 들어간다(파일을 열어 확인). 자세한 순서는 [배포-가이드.md](배포-가이드.md)의 'A 구성 따라 하기'.

```bash
npm run start:prod
```

- 운영 DB는 `server/data/wb-edu.sqlite`에 만들어지며 샘플 데이터는 들어가지 않는다.
- 휴대폰에서도 접속하려면 `.env.prod`의 `HOST=0.0.0.0`으로 바꾸고 같은 Wi‑Fi에서 `http://<PC IP>:3987`로 접속한다. 외부 인터넷에 열 때는 HTTPS 리버스 프록시를 앞에 두어야 한다.
- 로그인 후 **설정 → 내 계정**에서 비밀번호를 한 번 더 확인하고, **설정 → 사용자·권한**에서 강사 계정을 만든다.

백업은 하루 한 번:

```bash
npm run backup:prod
```

(`npm run backup`은 데모 DB를 백업한다. 운영 백업은 항상 `backup:prod`.) 자동 백업은 배포 가이드의 작업 스케줄러 등록으로 매일 돈다. 백업 파일은 `server/data/backups/`에 쌓이며 기본 60개를 넘으면 오래된 것부터 지운다.

## 2. 휴일 확인 (10분)

**설정 → 휴일**에서 2026년 목록을 열고, 정부 고시와 대조한 뒤 각 행의 '확인'을 체크한다.
기본 데이터는 2026-10-11에 공개 달력 자료와 대조해 날짜가 일치했으나, 임시공휴일 지정은 고시로 바뀔 수 있다.

- 포함됨: 신정, 설 연휴(2/16~18), 삼일절+대체(3/2), 어린이날, 부처님오신날+대체(5/25), 지방선거일(6/3), 현충일(6/6 토, 대체 없음), 광복절+대체(8/17), 추석 연휴(9/24~26, 토요일 대체 없음), 개천절+대체(10/5), 한글날, 성탄절
- 포함 안 됨(필요하면 직접 추가): 노동절 5/1, 제헌절 7/17, 학원 자체 휴무·방학
- 학원 휴무가 특정 반에만 해당하면 휴일 세트 대신 계획 만들기의 **상세 설정 → 휴강·방학**에 넣는다.

## 3. 교재 등록 (교재 1권당 20~40분)

1. **교재 보관함 → + 교재 등록**. 교재명·출판사·과목·학년·학기·판본(개정연도)·ISBN을 적고, 정보 확인 상태는 처음엔 '검토 중'.
2. **사용 범위·이용 권한 메모**에 어떤 근거로 사용하는지 적는다(구입 교재, 출판사 허용 범위 등).
3. 가장 빠른 방법: **표·목차·PDF 가져오기 → 목차 텍스트·PDF**에서 교재 PDF의 목차 페이지를 고르거나 목차를 그대로 붙여 넣는다. 줄 끝 쪽번호로 범위(다음 항목 시작 − 1)가 만들어지고 시간은 쪽당 분으로 추정된다. '본문 마지막 쪽'을 넣고 미리보기에서 확인한 뒤 적용, 이어서 아래 표에서 시간·분할·용도를 고친다. 스캔본처럼 글자가 없는 PDF는 목차를 직접 입력한다.
   목차 정보가 더 자세하면 엑셀이나 메모장에 [학습항목 붙여넣기 양식](templates/학습항목-붙여넣기-양식.tsv)대로 정리해 **표·엑셀 붙여넣기**로 넣는다. 열 순서는 자유이며 머리글만 맞으면 된다.
   - **단위**: 쪽 / 문항 / 지문 / 어휘 묶음 / 활동 / 강 / 단원 / 차시
   - **시작·끝**: 인쇄된 쪽수 기준 (PDF 페이지와 다르면 교재의 'PDF 페이지 보정'에 차이를 적는다)
   - **시간**: 실제로 그 범위를 수업하는 데 걸리는 분. 모르면 비워 두면 추정값으로 들어가고 '추정' 표시가 붙는다.
   - **분할**: 단원 평가·지문 하나처럼 중간에 끊으면 안 되는 항목은 '불가'
   - **용도**: 수업만 / 숙제만 / 수업·숙제
4. **표·엑셀 붙여넣기**로 붙여 넣고 미리보기에서 [오류]를 모두 고친 뒤 적용 → **저장**.
5. 정답·해설·부록은 **제외 범위**에 넣는다. 선수 학습이 분명한 항목(예: 2단원은 1단원 뒤)은 표에서 '선수 항목'을 지정한다. 확실한 것만 넣는다.
6. 자체교재는 **교재 구분: 자체교재**로 등록하고, 활동지의 '보충 연결'에서 주교재와 항목 제목을 선택한다. 주교재를 먼저 저장해 두면 교재별로 순서·제목·쪽 범위가 보인다. 연결하지 않으려면 '연결 안 함'을 고른다. 보관·제외된 대상은 새 후보에서 빠지고, 기존 연결은 상태 표시와 함께 보존된다. 보충형 과정에는 선택한 주교재도 넣는다.

## 4. 표준과정 만들기 (20분)

1. **표준과정·조립판 → + 과정 만들기**. 과정명(예: "독해 마스터 5-1 기본 진행안"), 대상(반 이름), 구성 방식 선택.
   - 교재 1권만: 순차형 · 주교재 + 활동지를 매 수업 함께: 병행형 · 주교재 단원 뒤에 활동지: 보충형
2. 교재를 추가하고 역할(주/부/보충)을 정한다. 특정 단원만 가르치면 '포함·제외 범위'에서 체크한다.
3. 회당 수업시간·복습·여유를 반 시간표대로 적고 **자동 구성**을 누른다. 결과는 초안이다.
4. 조립판에서 차시를 보며 이동·분할·묶기로 다듬는다. 분할 불가 항목은 자동으로 나뉘지 않는다. 미배정 항목이 남으면 차시를 추가하거나 범위를 조정한다.
5. 저장. 담당자가 검토했으면 **검증 완료·새 버전 발행**(이후 구조를 바꾸면 버전이 올라가고 초안으로 돌아간다).

## 5. 계획 만들기와 확정 (10분)

1. **계획 만들기** → 과정 선택 → 범위(전체 또는 중간부터) → 시작일·요일·시간·공휴일 세트 → **편성 결과 보기**.
2. 미배정이 있으면 보강일 추가·기간 연장·분할 허용 중 무엇으로 풀지 정한다. 분량을 지우거나 숙제로 돌리는 선택은 하지 않는다.
3. **초안으로 저장** → 상세 화면에서 통합 진도표(연/분기/월/주/일) 확인 → 이상 없으면 **확정**. 확정하면 사용한 교재 판본·과정 버전이 보존된다.
4. **출력 탭**에서 강사용 A4 인쇄 보기와 학생·학부모용 엑셀을 한 번씩 뽑아 본다.

## 6. 매일·매주 할 일

| 언제 | 누가 | 무엇을 | 어디서 |
|---|---|---|---|
| 수업 직후 | 강사 | 항목별 완료 / 부분 완료(어디까지) / 미진행 / 제외(사유) 입력. 부분 완료면 '남은 범위 이어서 진행' 누르기 | 휴대폰 → 오늘 수업 |
| 수업 직후 | 강사 | 이해가 확인된 항목은 '이해 확인 기록' 남기기 (계획에 있다고 습득으로 보지 않음) | 계획 상세 → 진도 기록 |
| 휴강이 생기면 | 강사·관리자 | 일정 수정 → 휴강 → 비교 보기 → 적용. 보강이 잡히면 보강일 추가 | 계획 상세 → 일정 수정 |
| 주 1회 | 관리자 | 주간 보기로 밀린 분량·미배정 확인, 필요하면 '남은 일정 재편성' | 계획 상세 → 통합 진도표 |
| 주 1회 | 관리자 | [피드백 기록](시범운영-피드백.md)에 불편·오류·요청 적기 | 문서 |
| 매일 | 자동 | 운영 DB 백업 (작업 스케줄러 등록 시 자동, 손으로는 `npm run backup:prod`) | 터미널 |

## 7. 시범 운영 종료 때 확인할 것

- 교재 완료율(교재별 진행 현황)과 실제 체감 진도가 맞는가
- 예상 소요시간 '추정' 항목 중 실제와 크게 다른 항목 → 교재의 분 값을 고치고 과정 새 버전 발행
- 복습·평가 위치가 적절했는가 (과정의 차시 marker·회당 복습 시간 조정)
- 출력물에서 학부모가 보기에 불필요하거나 부족한 열
- 피드백 기록을 바탕으로 다음 개발 우선순위 결정 ([가정과제한.md](가정과제한.md)의 후속 항목과 대조)

## 8. 문제가 생겼을 때

| 증상 | 조치 |
|---|---|
| "다른 사용자가 먼저 수정했습니다" | 최신 버전 불러오기 후 내 변경을 다시 입력 (자동 병합 없음) |
| 확정 버튼이 비활성 | 미배정 범위를 재편성·보강·제외로 정리. 선행 과정은 기초 확인 체크 필요 |
| 되돌리기가 거부됨 | 그 변경 이후 입력된 실제 기록이 있어서임. 기록은 지우지 않으므로 재편성으로 앞으로 맞춘다 |
| 서버가 안 뜸 | `npm run build` 했는지, `.env.prod`의 비밀번호가 비어 있지 않은지 확인. 포트 충돌이면 `PORT` 변경 |
| DB 복구 | 서버 중지 → `server/data/backups/`의 사본을 `server/data/wb-edu.sqlite`로 복사(기존 파일과 `-wal`, `-shm` 파일은 먼저 옮겨 둔다) → 서버 시작 |
