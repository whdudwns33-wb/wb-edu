| 8 | 확정된 계획의 선행 기초 확인을 바꿀 수 있음 | 확정 해제 후에만 바꿈 |
| 9 | 이해 확인이 그 수업에 없는 항목·꾸민 교재 id·목표 id 를 그대로 저장 | 그 수업에 배정된 항목만 받고, 교재는 배정에서, 목표는 항목의 목표 중에서만 |
| 10 | 달력 파일에서 맥 방식 줄바꿈(\r 단독)·제어 문자가 일정 줄을 깨뜨림 | \r 도 \n 으로 바꾸고 제어 문자 제거 |

브라우저 확인: 계획 화면이 옛 버전인 상태에서 다른 사람이 먼저 기록한 뒤 '완료'를 눌러, 화면에서 본 배정이 함께 전송되고 병합(200, merged)되는 것을 확인.

자동 테스트 총 150건 통과 (shared 106 + server API 44). 타입 검사·웹 빌드 오류 없음.

## 10차: 남은 후속 후보 두 가지 (휴대폰 끌어 놓기, 사진·스캔 2단 목차)

| 항목 | 자동 테스트 | 브라우저 확인 |
|---|---|---|
| 사진·스캔 2단 목차를 왼쪽 단 → 오른쪽 단 순서로 | shared 3건. 엔진이 두 단을 따로 읽은 경우와 한 줄로 합친 경우, 1단 목차, 그리고 **실제 엔진 결과**(가상 2단 목차 그림을 tesseract.js 7로 인식해 저장한 `shared/test/fixtures/ocr-2col-toc.json`) | 교재 등록 → 목차 사진에 가상 2단 목차 그림을 넣어 9줄이 '1단원 … 3단원 … 2단원 …' 순서, 한글 띄어쓰기 그대로 나옴. 1단 목차 사진의 'PART 1', 연도 '2023', 제목 속 '2 3'도 그대로 |
| 휴대폰 터치 끌어 놓기 (조립판) | — (화면 전용, 이동 로직은 기존 `moveEntry` 테스트) | 휴대폰 크기(375×812)에서 터치 이벤트로: 짧게 밀면 끌기가 시작되지 않고 스크롤 유지 / 0.35초 길게 누르면 카드 이름표가 손가락을 따라옴 / 판 오른쪽 끝에 손가락을 두면 차시 판이 가로로 넘어감 / 3차시에 놓아 1차시 카드가 3차시 끝으로 이동. 컴퓨터 마우스 끌어 놓기(차시 이동, 미배정으로 보내기)도 그대로 동작. 저장하지 않음 |

만들면서 찾은 것:
- 엔진의 단어 위치는 한글을 글자 단위로 쪼개고 서로 겹치기도 해, 위치로 띄어쓰기를 정하면 '요 약 하기'가 된다. 띄어쓰기는 엔진이 준 줄 텍스트에서 가져오고, 위치는 단을 나누는 데만 쓴다.
- 오른쪽 단의 대단원 줄은 항목보다 내어 쓰여 있어 단 경계보다 왼쪽에서 시작한다. 쪽번호가 없어 확실하지 않은 줄은 단 경계 근처의 넓은 빈칸에서 나눈다.
- 조립판 카드가 렌더마다 새 컴포넌트로 다시 만들어져, 길게 누른 순간 처음 누른 카드가 화면에서 떨어져 나가 터치 이벤트가 끊겼다. 카드를 함수로 그리게 바꾸고, 처음 누른 요소에 직접 이벤트를 단다.
- 점선 끝이 밑줄로 읽힌 찌꺼기('........ _36')를 지운다.
- 엔진이 영어 단어를 잘못 읽는 경우(가상 그림의 'Part A 어휘' → '2.PartAOIE')는 엔진 한계로, 사람이 고쳐야 한다.

자동 테스트 총 153건 통과 (shared 109 + server API 44).

## 하지 않기로 판단한 것

- **실시간 동시 타이핑(같은 칸을 여러 사람이 동시에 입력)**: 문서 동기화 구조(CRDT 등)와 상시 연결이 필요해 구조를 크게 바꾼다. 대신 다른 사람의 저장을 15초 안에 알리고, 진도 기록·이해 확인은 자동 병합하며, 그 밖의 저장은 409로 덮어쓰기를 막는다. 시범 운영에서 실제로 같은 문서를 동시에 고치는 일이 잦으면 다시 검토한다.
- **서버에서 PDF 파일 생성**: 한글 글꼴을 서버에 넣고 별도 조판을 만들어야 한다. A4 인쇄 보기 → 브라우저 'PDF로 저장'으로 요구사항의 PDF 출력을 이미 충족하며, 화면·엑셀과 같은 집계를 그대로 쓴다.

## 후속 개발 (남은 것)

시범 운영 피드백에 따라 정한다. 알려진 후보였던 휴대폰 터치 끌어 놓기와 사진·스캔 2단 목차의 단 순서는 10차에서 반영했다. 실제 휴대폰 기기의 손가락 조작은 시범 운영에서 확인한다(브라우저의 휴대폰 화면 흉내와 터치 이벤트로만 확인함).
