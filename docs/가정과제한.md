# 가정, 미구현 사항, 제한 사항

## 가정 (합리적 기본값으로 정한 것)

1. **저장소**: 단일 서버 SQLite 파일. 소규모 학원(수십 사용자, 수천 계획) 규모를 가정했다. 더 커지면 `Store` 계층만 교체하면 된다.
2. **인증**: 서버 세션 쿠키(14일). 외부 SSO·이메일 인증은 없다. 계정은 관리자가 만든다.
3. **권한 2단계**: 관리자 / 강사. 강사는 자기가 만든 계획과 '허용 강사'로 지정된 계획만 다룬다. 과정 단위 세부 권한(특정 과정만 허용)은 계획의 `allowedUserIds`로 대신한다.
4. **PDF**: 서버 PDF 렌더링 대신 A4 인쇄 보기 + 브라우저 '인쇄 → PDF로 저장'. 한글 폰트 내장 PDF 라이브러리 없이 동작하게 하기 위함.
5. **공휴일 기본 데이터**: 2026·2027년을 「관공서의 공휴일에 관한 규정」 일반 규칙으로 산출해 넣었고 전부 `verified=false`로 표시했다. 임시공휴일·대체공휴일 변경은 정부 고시를 확인해 설정 화면에서 수정해야 한다.
6. **학년도 시작월**: 기본 3월. 운영 설정과 계획별 설정에서 바꿀 수 있다.
7. **분할 규칙**: 범위형 항목은 시간 비율로 쪽·문항을 나누고, 수량형 항목은 10분 이상일 때만 5분 단위 비율로 나눈다. 최소 조각 5분.
8. **병행형 편성**: 같은 교재 안 순서는 지키고, 다른 교재 항목은 앞당겨 넣을 수 있다.
9. **숙제**: 수업시간과 별도이며 해당 차시의 수업 항목이 배정된 수업에 붙는다. 숙제 완료는 자동 처리하지 않는다.
10. **선수 학습**: 학습항목의 `prerequisiteItemIds`는 담당자가 입력한 확정 관계로 본다. 학습목표의 선수 관계는 `prerequisiteVerified`가 true인 것만 확정으로 쓴다.
11. **목표일 초과 사유**: 기간 우선 편성에서 종료일 없이 목표 완료일만 있을 때 목표일을 경계로 쓴다. 종료일이 있으면 목표일 초과는 경고로만 표시한다.
12. **시간 추정값**: 붙여넣기 가져오기에서 시간이 없으면 쪽당 5분(범위형) 또는 30분으로 추정하고 `estimated`로 표시한다.
13. **샘플**: 가상 시중교재 1권(독해 마스터 5-1, 8항목×30분)과 가상 자체교재 1종(활동지 8개×15분)만 제공한다. 실제 교재 자료는 넣지 않았다.
14. **동시 수정**: 문서 version 불일치 시 409로 거부하고 화면에서 최신 버전을 다시 불러오게 한다(자동 병합 없음).

## 미구현 사항 (첫 실사용 버전 범위 밖 또는 후속)

- 목차 인식은 **텍스트가 들어 있는 PDF**와 **복사한 목차 텍스트**만 지원한다(브라우저 안에서 pdf.js로 읽고 서버로 보내지 않음). 사진·스캔 PDF의 글자 인식(OCR)은 외부 언어 데이터가 필요해 넣지 않았다. 목차 줄 끝의 쪽번호가 없거나 2단 편집으로 줄이 섞이면 결과를 손으로 고쳐야 한다.
- 공동 편집은 **변경 알림**까지다. 같은 문서를 다른 사람이 저장하면 15초 안에 배너로 알리고, 저장 시 409로 덮어쓰기를 막는다. 실시간 동시 입력·자동 병합은 없다.
- 외부 연동 (4단계 후속 범위).
- 서버 측 PDF 생성(현재는 브라우저 인쇄).
- 조립판 드래그 앤 드롭은 컴퓨터 마우스용(HTML5 drag & drop)이다. 휴대폰 터치에서는 동작하지 않으므로 기존 버튼·선택 이동을 쓴다.
- 출력 양식의 열 선택은 연간·분기·월간 표에는 적용되지 않고(고정 구성), 주간·일간 표에만 적용된다. 학생·학부모용 양식에서는 내부 열(지도 메모·점검 사항·시간 배분·PDF 페이지·기록 메모)을 선택해도 출력하지 않는다.
- 교재 학습항목 편집 화면의 '보충 연결(attachToItemId)'은 항목 id 직접 입력 방식이다(선택 UI 후속).
- 비밀번호 찾기. 로그인 실패 제한은 서버 메모리 기준(같은 IP·아이디 15분 내 10회 실패 → 15분 잠금)이라 서버를 재시작하면 초기화되고, 여러 서버 인스턴스 간에는 공유되지 않는다. 일반 API 요청 속도 제한은 없다.
- HTTPS 종단(리버스 프록시 앞단에 두는 것을 전제).

## 제한 사항·주의

- 운영 DB(`WB_MODE=prod`)는 별도 파일이며 샘플을 자동으로 넣지 않는다. 데모 DB에서 만든 데이터는 운영으로 자동 이전되지 않는다.
- 되돌리기는 해당 변경 이후 입력된 실제 기록이 있으면 거부된다(기록 보호). 필요하면 재편성으로 앞으로 나아가야 한다.
- 확정 계획은 스냅샷 갱신을 막는다. 초안 계획도 실제 기록이나 고정 배정이 생기면 갱신을 막는다(새 과정 구조와 기존 진행을 안전하게 맞출 수 없으므로). 교재·과정 개정분을 적용하려면 계획을 복제해 갱신하거나 새 계획을 만든다.
- 초안(미검증) 과정으로도 계획을 만들 수 있다(화면에 '초안' 표시). 보관된 과정으로는 만들 수 없다.
- 속도 우선 편성은 최대 탐색 일수(기본 400일, 최대 1500일) 안에서만 완료 예정일을 찾는다.
- 휴강 사유·보강일·제외 사유 등은 앱 모달(`usePrompt`)로 입력한다 (2차 검증에서 브라우저 대화상자를 교체).
- 보강일은 시작일 이후여야 하며, 종료일 이후 보강일은 수업일 범위를 그 날짜까지 넓힌다.
- 벤치마킹은 공식 공개 설명과 화면을 확인한 수준이며, 로그인 후 전체 기능을 검증한 것은 아니다. 디딤돌의 로그인 필요 PDF 본문은 검증되지 않았다.
