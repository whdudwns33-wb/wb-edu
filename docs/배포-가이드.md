# 배포 가이드 (학원 PC 또는 소형 서버)

전제: 시범 운영 가이드대로 `.env.prod`를 만들고 `npm run build`가 끝난 상태. 앱 자체는 HTTPS를 처리하지 않으므로, 외부에서 접속한다면 리버스 프록시를 앞에 둔다.

## A 구성 따라 하기: 학원 PC 한 대 (그 PC에서만 사용)

운영할 PC에서 차례대로 한다. 같은 PC에 데모 DB가 있어도 운영 DB는 별도 파일이라 섞이지 않는다.

**1. 설치** — Node.js 22.13 이상(LTS)과 Git을 설치하고 저장소를 받는다.

```bash
git clone https://github.com/whdudwns33-wb/wb-edu.git
```

```bash
cd wb-edu
```

```bash
npm install
```

```bash
npm run build
```

**2. 운영 준비 점검** — `.env.prod`가 없으면 만들어 주고, 초기 관리자 비밀번호를 무작위로 넣는다(화면에는 보이지 않으니 `.env.prod`를 메모장으로 열어 확인). Node 버전·빌드·접속 주소(127.0.0.1)·DB 분리를 점검한다.

```bash
npm run setup:prod
```

**3. 처음 한 번 직접 실행** — 브라우저에서 `http://127.0.0.1:3987`에 접속해 관리자로 로그인한다.

```bash
npm run start:prod
```

- 설정 → 내 계정에서 비밀번호를 바꾼다. 바꾼 뒤에는 `.env.prod`의 `WB_ADMIN_PASSWORD` 줄을 지워도 된다(첫 실행에만 쓰임).
- 설정 → 사용자·권한에서 강사 계정을 만든다. 설정 → 휴일에서 올해 휴일을 확인한다.
- 확인이 끝나면 터미널에서 Ctrl+C로 서버를 끈다.

**4. 자동 시작·매일 백업 등록** — 관리자 PowerShell에서 저장소 폴더로 이동해 실행한다. 서버는 로그온할 때 창 없이 켜지고(창을 실수로 닫아 꺼지는 일이 없음), 기록은 `server\data\logs\`에 남는다. 바탕화면에 'WB 커리큘럼 플래너' 바로가기가 생긴다.

```bash
powershell -ExecutionPolicy Bypass -File deploy\windows\register-tasks.ps1
```

**5. 확인** — PC를 다시 로그온하거나 아래 명령으로 바로 켠 뒤 바로가기로 접속한다. 백업 작업도 한 번 돌려 `server\data\backups\`에 파일이 생기는지 본다.

```bash
powershell -ExecutionPolicy Bypass -File deploy\windows\server-control.ps1 start
```

```bash
powershell -Command "Start-ScheduledTask -TaskName 'WB Planner Backup'"
```

운영 서버가 3987을 쓰는 PC에서 개발·확인용 데모 서버를 함께 띄울 때는 `npm run start:demo`(3988 포트, 데모 DB)를 쓴다.

손으로 백업할 때는 `npm run backup:prod`를 쓴다(`npm run backup`은 데모 DB를 백업한다). 백업은 다른 디스크나 USB에도 주기적으로 복사해 둔다. `.env.prod`에 `WB_BACKUP_DIR=D:/wb-edu-backups`처럼 적으면 처음부터 다른 곳에 저장된다.

운영 명령은 환경 파일에 `WB_MODE=demo`가 있어도 운영 모드를 유지하며, 데모 DB를 운영 DB 경로로 지정하면 중단한다. `WB_DB_PATH`, `WB_BACKUP_DIR`, `WB_LOG_DIR`, `WB_STATIC_DIR`의 상대 경로는 모두 저장소 루트 기준이다. 셸에 지정한 환경변수가 파일보다 우선하므로 `setup:prod`도 실제 적용될 값을 점검한다. 초기 관리자 비밀번호는 10~1024자이며, 기존 계정이 있으면 초기값을 지워도 재점검·재시작할 수 있다.

보관 개수를 바꾸려면 `npm run backup:prod -- --keep 30`처럼 1 이상의 정수를 넣는다. 음수·0·소수·빈 값은 백업을 건드리기 전에 거절한다. 숨김 서버의 첫 실행 실패도 로그 파일에 남는다.

## 구성 선택

| 구성 | 접속 범위 | 필요한 것 |
|---|---|---|
| A. 학원 PC 한 대, 그 PC에서만 사용 | 그 PC | `.env.prod` HOST=127.0.0.1, 자동 시작 작업 |
| B. 학원 내부 Wi‑Fi에서 휴대폰·태블릿도 사용 | 같은 네트워크 | HOST=0.0.0.0 또는 Caddy `tls internal`(자체 서명, 브라우저 경고 1회), PC 방화벽에서 포트 허용 |
| C. 외부 인터넷에서 사용 | 어디서나 | 도메인 + 공인 IP(또는 터널) + Caddy HTTPS, 강한 비밀번호, 정기 백업 |

C 구성에서는 앱이 127.0.0.1:3987에서만 듣게 두고 Caddy만 외부에 노출한다. 앱은 같은 IP·아이디로 15분 안에 10회 실패하면 15분 동안 로그인을 잠그고 실패를 감사 로그에 남긴다. 프록시 뒤에서는 모든 요청이 프록시 IP로 보일 수 있으므로, IP 단위 제한은 방화벽·프록시에서도 함께 건다.

## Windows 자동 시작·자동 백업 (작업 스케줄러)

관리자 PowerShell에서 저장소 루트로 이동한 뒤:

```bash
powershell -ExecutionPolicy Bypass -File deploy\windows\register-tasks.ps1 -BackupTime 23:00
```

- `WB Planner Server`: 로그온 시 창 없이 `node scripts/start-prod.mjs --log-file` 실행, 실패 시 1분 간격 3회 재시작. 기록은 `server/data/logs/server-YYYY-MM.log`
- `WB Planner Backup`: 매일 지정 시각에 운영 DB 백업 (`npm run backup:prod`와 같음, `.env.prod`의 `WB_BACKUP_DIR` 사용)
- 바탕화면 바로가기 'WB 커리큘럼 플래너' (`-NoShortcut`이면 만들지 않음)
- 제거: 같은 스크립트에 `-Remove` (작업과 바로가기 삭제)
- 서버 켜기·끄기·다시 시작·상태: `deploy\windows\server-control.ps1 start|stop|restart|status` (관리자 권한 필요 없음). 작업 스케줄러의 '작업 끝내기'(`Stop-ScheduledTask`)는 숨긴 PowerShell 창만 닫고 서버(node) 프로세스를 남기므로 이 스크립트를 쓴다. 남은 서버가 포트를 쥐고 있으면 새 서버가 뜨지 못한다.
- PC를 로그온 없이 켜 두는 경우(서버 용도)라면 작업의 "사용자 로그온 여부에 관계없이 실행"을 작업 스케줄러 UI에서 켠다.

## HTTPS 리버스 프록시 (Caddy)

[deploy/Caddyfile.example](../deploy/Caddyfile.example)을 복사해 도메인을 바꾼다.

```bash
caddy run --config Caddyfile
```

Windows에서는 Caddy도 작업 스케줄러나 `caddy` 서비스로 등록한다(공식 문서의 `caddy service` 참고). 쿠키는 `SameSite=Lax`, `HttpOnly`이며 HTTPS 뒤에서는 그대로 동작한다.

## 업데이트 절차

```bash
git pull
```

```bash
npm install
```

```bash
npm run build
```

이후 서버를 다시 시작한다.

```bash
powershell -ExecutionPolicy Bypass -File deploy\windows\server-control.ps1 restart
```

 DB 스키마는 서버 시작 시 자동으로 만들어지며, 문서 JSON은 누락 필드를 기본값으로 다루므로 별도 마이그레이션이 없다. 업데이트 전에는 항상 `npm run backup:prod`를 먼저 실행한다.

## 복구

1. 서버 중지: `deploy\windows\server-control.ps1 stop`
2. `server/data/wb-edu.sqlite`, `-wal`, `-shm` 파일을 다른 폴더로 옮긴다
3. `server/data/backups/`에서 원하는 시점의 사본을 `server/data/wb-edu.sqlite`로 복사
4. 서버 시작: `deploy\windows\server-control.ps1 start`

## 점검 목록

- [ ] `.env.prod`의 관리자 비밀번호가 기본값이 아님, 로그인 후 한 번 더 변경
- [ ] 강사 계정은 역할 '강사'로 만들고 필요한 계획에만 허용
- [ ] 백업 작업이 매일 실행되고 파일이 늘어나는지 1주 뒤 확인 (`server/data/backups/`), 서버 기록에 오류가 없는지 확인 (`server/data/logs/`)
- [ ] `.env.prod`의 초기 비밀번호 줄은 앱에서 비밀번호를 바꾼 뒤 지움
- [ ] 외부 접속이면 HTTPS 적용, HTTP 직접 노출 금지
- [ ] 샘플 데이터는 운영 DB에 없음(설정 → 샘플 데이터 0건)
